# Агент заселения

AI-агент, который принимает заявки на заселение гостей в квартиры: разбирает
сообщение гостя, считает цену по календарю и тарифам, отвечает и доводит заявку
до брони. Всё работает в браузере, без сервера и без базы данных.

Демо: откройте `zaselenie/index.html` — слева переписка, справа видно, **что именно
агент понял** и почему ответил так, а не иначе.

## Главная идея: считает движок, говорит модель

Обычный чат-бот на одной большой языковой модели уверенно называет цену, которой
нет в прайсе, и обещает квартиру, которая занята. Здесь эти роли разделены:

| Слой | Отвечает за | Файл |
|---|---|---|
| Разбор | даты, гости, бюджет, требования, скрытые сигналы | `js/nlu.js` |
| База знаний | квартиры, тарифы, сезоны, правила, занятость | `js/knowledge.js` |
| Расчёт | цена ночи, подбор, доступность, скидки, возвраты | `js/policy.js` |
| Риск | вечеринка, субаренда, мошенничество, документы | `js/risk.js` |
| Сценарии | что это за обращение и что с ним делать | `js/scenarios.js` |
| Оркестратор | память диалога, решение, заявка для CRM | `js/agent.js` |
| Модель | формулировка ответа живым языком | `js/api.js` + `prompts/` |

Модель получает уже посчитанные факты и **не может выдумать цену или свободную
дату** — их просто нет в её входных данных, кроме как из расчёта.

## Как агент разбирает запрос

Одно сообщение проходит семь шагов:

1. **Нормализация и язык** — регистр, «ё», латиница, узбекский и английский.
2. **Слоты** — даты («с 3 по 7 марта», «завтра на 2 ночи», «на выходные»,
   «в начале мая», «12.03–15.03»), число гостей («нас двое взрослых и ребёнок
   4 года», «семья из 5», «вдвоём»), бюджет («до 600 тысяч за ночь», «50$»),
   район, комнатность, требования (лифт, парковка, кроватка, рабочее место).
3. **Сигналы** — то, что сказано между строк: «отметить», «на пару часов»,
   «без паспорта», «верните на другую карту», «пересдавать», «прилетаем в 2 ночи».
4. **Память диалога** — слоты копятся: «нас четверо» из первого сообщения
   работает и в пятом, выбор «беру второй вариант» превращается в бронь.
5. **Подбор и расчёт** — по календарю занятости, с сезонами, выходными,
   доп. местами, питомцем, ранним заездом, скидками за срок.
6. **Риск** — 16 правил со своими весами; каждый флаг объясняет себя и говорит,
   что делать менеджеру.
7. **Сценарий и решение** — `ask`, `offer`, `hold`, `confirm`, `info`, `decline`,
   `escalate`, `handoff`, `ignore`; плюс текст ответа, заметка менеджеру и
   структурированная заявка для CRM.

Всё, что пришлось предположить, агент проговаривает вслух: «беру ближайшие
выходные, подтвердите» — чтобы гость успел поправить до брони.

## Сценарии

Полное описание — в [`prompts/scenarios.md`](prompts/scenarios.md), реализация —
в `js/scenarios.js` (идентификаторы совпадают).

**Стоп-темы (отказ или человек):** незаконное использование · схемы с оплатой ·
субаренда · прописка без проживания · гость младше 18 · заселение без паспорта ·
квартира под склад · вечеринка · почасовая аренда · агрессия и угрозы.

**Гость уже живёт:** авария и «не могу попасть в квартиру» · жалоба на квартиру ·
ущерб и депозит · потерянные ключи.

**Изменения брони:** отмена с расчётом возврата · перенос дат с пересчётом ·
продление с проверкой следующего заезда.

**Особые заявки:** группа на несколько квартир · длительная аренда от месяца ·
командировка со счётом и актом · регистрация и миграционный учёт.

**Даты:** выезд раньше заезда · дата в прошлом · «где-то в мае» · меньше
минимального срока · всё занято (окна ±14 дней и лист ожидания).

**Путь брони:** неполная заявка → уточнение → варианты с ценой → удержание →
контакты → предоплата и адрес.

**Вопросы:** цена · наличие · скидка · адрес · оплата и «без предоплаты» ·
животные · доступность и лифт · время заезда · быт (Wi-Fi, кухня, стирка,
парковка, трансфер) · «позовите человека» · спам · другой язык · не понял.

## Настройка под свой бизнес

Правится один файл — [`js/knowledge.js`](js/knowledge.js):

- `KB.settings` — бренд, город, валюта, время заезда и выезда, предоплата,
  депозиты, доплаты (питомец, доп. гость, ночное заселение), лестница возвратов,
  скидки за срок, контакты менеджера;
- `KB.objects` — квартиры: вместимость, район, этаж и лифт, базовая цена,
  коэффициент выходного дня, минимальный срок, депозит, животные, парковка,
  удобства, занятые даты;
- `KB.seasons` — сезонные коэффициенты и пиковые даты (Новый год, Навруз);
- `KB.faq` — короткие ответы на бытовые вопросы.

Ни одна цена и ни одно правило не зашиты в текстах ответов — они собираются
из этих данных, поэтому смена тарифа не требует правки сценариев.

Занятость в демо задана сдвигом от сегодняшнего дня, чтобы примеры не протухали.
В бою на её место подставляется выгрузка из вашей системы бронирования (тот же
формат: `{ from, to }` в `obj.busy`).

## Режим с Claude

Кнопка «Движок + Claude» в шапке. Нужен ключ API — он хранится только в
localStorage браузера и уходит напрямую в Anthropic.

Схема вызова: движок считает факты → они уходят в блоке `<факты>` вместе с
системным промптом из [`prompts/system.md`](prompts/system.md) → модель пишет
ответ в блоке `<ответ>` и заметку менеджеру в `<заметка>`.

**Для боевого бота ключ в браузере не годится** — его увидит каждый, кто откроет
страницу. В продакшене `js/api.js` заменяется на вызов вашего сервера, который
уже ходит в Anthropic со своим ключом.

## Подключение к мессенджеру

Движок не зависит от браузера — это обычные модули. Скелет бота:

```js
['util','knowledge','nlu','policy','reply','risk','scenarios','agent']
  .forEach(m => require('./zaselenie/js/' + m + '.js'));

const sessions = new Map();                       // чат → контекст диалога

async function onMessage(chatId, text) {
  if (!sessions.has(chatId)) sessions.set(chatId, AGENT.newContext({ channel: 'telegram' }));
  const res = AGENT.respond(text, sessions.get(chatId));

  await send(chatId, res.reply);                  // ответ гостю
  if (res.escalate) await notifyManager(res);     // позвать человека
  await saveLead(res.crm);                        // заявка в CRM или таблицу
}
```

`res.crm` — готовая заявка: даты, гости, требования, предложенные варианты
с ценами, оценка риска, чего не хватает и следующий шаг.

## Тесты

```bash
node zaselenie/tests/run.js          # все наборы разом
node zaselenie/tests/nlu.test.js     # разбор дат, гостей, бюджета, сигналов
node zaselenie/tests/policy.test.js  # цены, занятость, подбор, возвраты
node zaselenie/tests/scenarios.test.js
```

Сценарные тесты проверяют, что на каждое типовое обращение выбирается нужная
ветка, что сложный запрос разбирается целиком (даты + дети + питомец + ночной
приезд + лифт + бюджет + документы) и что диалог из нескольких сообщений
доходит до брони.

Посмотреть ответы в терминале:

```bash
node zaselenie/tools/demo.js                       # 16 типовых заявок
node zaselenie/tools/demo.js "нас 14, 5-7 ноября"  # своё сообщение
```

## Что агент делает сам, а что отдаёт человеку

Сам: подбор и расчёт, удержание дат, уточнения, отказы по правилам, справки,
скидки до 10%, инструкции по заселению.

Человеку: деньги сверх политики и любые спорные платежи, аварии и ущерб,
конфликты и угрозы, брони дороже 10 млн и дольше 28 ночей, а также любой диалог,
где агент третий раз подряд задаёт уточняющий вопрос — значит, переписка
буксует и нужен живой менеджер.

## Ограничения

- Демо-данные: шесть квартир и выдуманные цены — это витрина, а не прайс.
- Занятость в памяти: нет реального календаря и блокировки дат при удержании.
- Разбор рассчитан на русский, узбекский и английский распознаются, но
  отвечает движок по-русски (в режиме с Claude — на языке гостя).
- Оплаты, чеки и отправка документов не реализованы: агент доводит до момента
  «реквизиты отправлены», дальше работает ваша система.

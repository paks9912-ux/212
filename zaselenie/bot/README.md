# Телеграм-бот агента заселения

Тот же движок, что и в демо, только вместо страницы — Telegram. Зависимостей нет:
нужен только Node 18+ (встроенные `fetch` и `http`).

## Запуск за три шага

1. **Создать бота.** В Telegram написать [@BotFather](https://t.me/BotFather) →
   `/newbot` → имя и адрес бота → он выдаст токен вида `123456789:AA...`.
2. **Прописать токен.**

   ```bash
   cp zaselenie/bot/.env.example zaselenie/bot/.env
   # вписать TELEGRAM_BOT_TOKEN
   ```
3. **Запустить.**

   ```bash
   node zaselenie/bot/telegram.js
   ```

В логе появится `бот @ваш_бот запущен в режиме polling`. Всё, можно писать боту
в Telegram — он отвечает теми же сценариями, что и демо-страница.

## Что бот умеет из коробки

- **Подбор и расчёт**: «с 12 по 15 ноября, нас трое, с котом» → варианты с ценами,
  депозитом и предоплатой.
- **Кнопки под вариантами**: «Беру: Лофт на Чиланзаре», «Другие даты»,
  «Позвать менеджера» — нажатие идёт в агента как обычная реплика.
- **Кнопка «Отправить мой номер»** на шаге брони: телефон и имя попадают в заявку
  без ручного ввода.
- **Память диалога**: «нас четверо» из первого сообщения работает и в пятом.
  Диалоги лежат в `sessions.json` и переживают перезапуск бота.
- **Вложения**: голосовые, фото и файлы без подписи → просьба написать текстом;
  подпись к фото читается как обычное сообщение.
- **Команды**: `/start`, `/help`, `/reset`, а у менеджера ещё `/stats`.
- **Границы**: в чужих группах молчит, на спам не отвечает, при флуде (больше 20
  сообщений в минуту) притормаживает.
- **Длинные ответы** режет на части — лимит Telegram в 4096 символов не ломает бота.

## Один фонд на несколько чатов

Бот держит общий реестр «мягких» броней: пока гость из одного чата думает час,
его даты не показываются гостям из других чатов, а второму агент честно
объясняет, что даты держит кто-то другой. Реестр сохраняется вместе с сессиями,
поэтому перезапуск бота не приводит к двойной продаже. Текущее число удержаний
видно в `/stats` у менеджера.

## Эскалация менеджеру

Заполните `MANAGER_CHAT_ID` — и на каждое обращение, где агент решил позвать
человека (мошенническая схема с оплатой, авария у живущего гостя, ущерб,
агрессия, крупная бронь), менеджеру прилетит карточка:

```
Нужен человек — Мошенническая схема с оплатой
Гость: Азиз @aziz · chat id 123456789
Сообщение: «я перевёл лишнее, верните на другую карту»
Сценарий: fraud · решение: escalate · риск 80 (критический)
Флаги: схема с чужой картой, «лишним переводом» или кодом из СМС
Ответ бота: По оплате работаем только так…
```

Свой chat id проще всего увидеть в логе бота после первого сообщения.
Для группы: добавить бота в группу, написать там что-нибудь и взять id из лога
(у групп он отрицательный).

## Режим с Claude

Добавьте `ANTHROPIC_API_KEY` — и ответы начнёт формулировать модель, а движок
останется источником фактов: цены, свободные даты и правила приходят ей уже
посчитанными, выдумать их она не может. Если модель недоступна, отказала или
ответила слишком долго, гость всё равно получает ответ движка — бот не молчит.

Здесь ключ живёт на сервере в переменной окружения, в браузер он не попадает.
По умолчанию используется `claude-opus-5`; сменить — `CLAUDE_MODEL`.

## Polling или webhook

- **polling** (по умолчанию) — бот сам опрашивает Telegram. Ничего наружу
  открывать не нужно, работает хоть с ноутбука. Подходит для старта и небольших
  потоков.
- **webhook** — Telegram сам стучится к вам. Нужен домен с https:

  ```bash
  BOT_MODE=webhook
  WEBHOOK_URL=https://bot.example.com/telegram
  WEBHOOK_SECRET=любая-длинная-строка
  PORT=8080
  ```

  Секрет проверяется в заголовке `X-Telegram-Bot-Api-Secret-Token`: чужой запрос
  на ваш адрес бот не обработает. Https обычно вешают через nginx или Caddy
  перед этим портом.

## Как держать бота запущенным

```ini
# /etc/systemd/system/zaselenie-bot.service
[Unit]
Description=Агент заселения — телеграм-бот
After=network-online.target

[Service]
WorkingDirectory=/opt/212
ExecStart=/usr/bin/node /opt/212/zaselenie/bot/telegram.js
EnvironmentFile=/opt/212/zaselenie/bot/.env
Restart=always
RestartSec=5
User=bot

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now zaselenie-bot
journalctl -u zaselenie-bot -f
```

При остановке (`SIGTERM`, `Ctrl+C`) бот сохраняет диалоги на диск, поэтому
перезапуск не теряет контекст гостей.

## Под свой бизнес

Квартиры, цены, правила и тексты — в [`../js/knowledge.js`](../js/knowledge.js).
Бот берёт их оттуда же, что и демо-страница: поправили тариф — изменились ответы
и в чате, и в браузере. Сценарии — в [`../js/scenarios.js`](../js/scenarios.js),
их описание — в [`../prompts/scenarios.md`](../prompts/scenarios.md).

Занятость квартир сейчас в `knowledge.js`. В бою на её место подставляется
выгрузка из вашей системы бронирования — формат тот же: `obj.busy = [{ from, to }]`.

## Проверка

```bash
node zaselenie/tests/bot.test.js    # телеграм-слой на подставном транспорте
node zaselenie/tests/run.js         # весь агент целиком
```

Тесты прогоняют диалог до брони, нажатие кнопок, отправку контакта, эскалацию
менеджеру, спам, флуд, команды и падение модели — без обращения к настоящему
Telegram.

## Персональные данные

В `sessions.json` попадают имена и телефоны гостей — это личные данные, поэтому
файл в `.gitignore` и на сервере его стоит держать с правами `600`. Диалоги
чистятся сами через `SESSION_TTL_HOURS` (по умолчанию 48 часов). Фото паспортов
бот не хранит: он просит их прислать, а работает с ними уже менеджер.

## Чего в боте нет

- Приёма платежей: агент доводит до «реквизиты отправлены», дальше ваша касса.
- Отправки фото квартир: подставьте `sendPhoto` там, где сценарий обещает фото.
- Общей базы для нескольких процессов: сессии лежат в файле, бот рассчитан на
  один экземпляр. Для нескольких инстансов замените `sessions.js` на Redis.

# ЧАСТЬ 1 — UX AUDIT

## 1.1. User journey

Реальный путь от входа до заказа, по шагам:

| Шаг | Что видит пользователь | Экранов прокрутки |
|---|---|---|
| 1 | Анимация текста `TASTE → SILENCE → KYOTO` над абстрактной геометрией | **6** |
| 2 | «ТОЧНОСТЬ в каждом движении» | 1 |
| 3 | **MENU — первая еда на сайте** | 2 |
| 4 | «Вам не нужно выбирать» (Omakase) | 1 |
| 5 | «Не просто ужин. Состояние.» | 1 |
| 6 | Форма брони стола, 7 полей | 1.5 |
| 7 | Футер | 0.5 |

```css
.hero{ height:600vh; }     /* строка 168 */
```

**Первая фотография еды появляется примерно на 8-м экране прокрутки.**
До неё — шесть экранов скролл-джекинга: страница прокручивается, но
контент не меняется, вместо этого проигрывается анимация типографики,
привязанная к позиции скролла.

На мобильном это ~6–8 полноэкранных свайпов, во время которых человек
не получает ни одного ответа на вопрос «что здесь можно купить и почём».

**Вывод:** сайт построен как имиджевая презентация ресторана, к которой
в середине прикручен каталог. Не как сервис доставки.

## 1.2. Navigation

```html
<nav class="nav">          <!-- строка 2076 -->
```
```css
.nav{ position:absolute; top:0; }   /* строка 117 — внутри .hero */
```

Навигация состоит из трёх элементов: логотип, надпись `Japanese dining experience`
и кнопка корзины. **Ссылок на разделы в шапке нет вообще.**

Шапка спозиционирована `absolute` внутри hero-секции. Это значит: как только
пользователь прокрутил первые 6 экранов, **шапка вместе с корзиной физически
уезжает за пределы экрана и больше не возвращается.**

На 90% высоты страницы у пользователя нет:
- ссылки на меню,
- ссылки на доставку,
- ссылки на контакты,
- **доступа к корзине.**

Единственная навигация по разделам — в футере, то есть в самом низу.

## 1.3. Information architecture

Порядок разделов на текущем сайте:

```
Hero (имидж) → Ритуал (имидж) → МЕНЮ → Омакасе (имидж) → Опыт (имидж) → Бронь → Футер
```

Из 7 блоков **4 имиджевых, 1 коммерческий (меню), 1 форма брони.**
Соотношение «продающего» к «декоративному» — примерно 1 : 4 по высоте.

Отсутствуют разделы, обязательные для доставки еды:
- **Доставка** — условий, зон, стоимости и сроков нет нигде на сайте.
- **Хиты / популярное** — нет.
- **Акции** — нет.
- **О ресторане / контакты** как раздел — только строчка в футере.
- **Режим работы** — нет.

Нумерация `01/05 … 05/05` в углах секций создаёт ощущение презентации-портфолио,
а не магазина.

## 1.4. Menu discovery

```html
<button class="menu-tab active" data-category="sushi">SUSHI</button>
<button class="menu-tab" data-category="rolls">ROLLS</button>
<button class="menu-tab" data-category="sets">SETS</button>
<button class="menu-tab" data-category="sake">SAKE</button>
```

- 4 категории, названия **латиницей**, при том что весь остальной контент на русском.
- Таб по умолчанию — `SUSHI`, то есть самый дешёвый и не самый популярный раздел.
- Категории **не sticky** — при прокрутке вниз переключатель уходит вверх,
  и чтобы сменить категорию, нужно скроллить обратно.
- Нет поиска, нет сортировки, нет фильтров, нет счётчика позиций в категории.
- Нет категории «Хиты» — пользователю негде увидеть, что берут чаще всего.

## 1.5. Product discovery

Всего в каталоге **12 позиций**:

| Категория | Позиций |
|---|---|
| sushi | 3 |
| rolls | 3 |
| sets | 3 |
| sake | 3 |

Ни у одного товара нет: бейджа, признака популярности, состава, веса, граммовки,
количества штук (кроме как внутри текста описания), аллергенов, времени приготовления.

Карточка товара — терминальная точка: отдельной страницы блюда нет, а значит нет
и ссылки, которую можно дать в рекламе или прислать другу.

## 1.6. Add-to-cart flow

Здесь находится одна из самых дорогих ошибок сайта.

```js
button.addEventListener("click", ()=>{
    const productId = button.dataset.id;
    if(cart[productId]){        // строка 4272
        openCart();             // ← второй клик НЕ добавляет товар
        return;
    }
    addToCart(productId);
});
```

**Первый клик** — товар добавлен, кнопка меняет текст на
`ДОБАВЛЕНО · 1 → КОРЗИНА`.
**Второй клик по той же кнопке количество не увеличивает — он открывает корзину.**

Чтобы заказать два одинаковых ролла, нужно:
1. нажать «Добавить»,
2. нажать ещё раз → открылась корзина,
3. найти позицию,
4. нажать `+`,
5. закрыть корзину,
6. вернуться к меню.

**6 действий вместо одного.** Для набора корзины из 5 позиций по 2 штуки это
превращается в 25+ действий и несколько открытий/закрытий панели.

Дополнительно: после добавления вызывается `renderProducts()`, который
перерисовывает **всю сетку целиком** и восстанавливает scroll через
`window.scrollTo()` — на слабых телефонах это заметный подскок.

## 1.7. Cart

**Видимость.** Корзина доступна только в hero (см. 1.2). После прокрутки — недоступна.
На мобильном её нет ни в каком виде на протяжении почти всей страницы.

**Индикация.** Показывается только количество товаров (`cartCount`), **сумма не показывается**
нигде до открытия панели.

**Содержимое панели.**

```html
<div class="cart-item">
  <div class="cart-item-name">   <!-- 11px -->
  <div class="cart-item-price">  <!-- 9px, серый 40% -->
  <button class="qty-button">    <!-- 25×25px -->
```

- **Нет фотографии товара** — пользователь не видит, что заказал.
- Показана цена за штуку, **сумма по позиции не показана**.
- **Нет кнопки «удалить»** — чтобы убрать позицию, нужно нажимать `−` до нуля.
- Кнопки количества **25×25px** при рекомендованном минимуме 44×44.
- Кнопка закрытия — 35×35px.
- Нет строки доставки, нет минимальной суммы заказа, нет апсейла.

**Плюс, который надо сохранить:** корзина переживает перезагрузку страницы —
`localStorage`, ключ `kyoto-cart`.

## 1.8. Checkout — ГЛАВНЫЙ ДЕФЕКТ САЙТА

```js
document.getElementById("checkoutButton").addEventListener("click", async ()=>{
    const items = Object.values(cart);
    let message = `<b>🍱 НОВЫЙ ЗАКАЗ — KYOTO</b>\n\n`;
    items.forEach((item, idx) => {
        message += `${idx+1}. <b>${item.name}</b> x ${item.quantity} = ...\n`;
    });
    message += `\n<b>ИТОГО: ...</b>`;
    const sent = await sendTelegramMessage(message);
    ...
    showToast("ЗАКАЗ УСПЕШНО ОТПРАВЛЕН!");
});
```

**Checkout-а не существует.** Кнопка «ОФОРМИТЬ ЗАКАЗ» отправляет в Telegram
список блюд — и всё.

В сообщении, которое получает ресторан, **нет**:
- имени,
- телефона,
- адреса,
- способа получения (доставка или самовывоз),
- комментария,
- времени.

Ресторан получает анонимный список блюд, который **физически невозможно выполнить.**
При этом пользователю показывается `ЗАКАЗ УСПЕШНО ОТПРАВЛЕН!` — то есть человек
уверен, что заказал еду, и ждёт курьера, который никогда не приедет.

Это не проблема дизайна. Это функциональный дефект, который делает бесполезной
всю остальную работу сайта.

Отдельно: форма контактов на сайте **есть** — но она обслуживает бронь стола,
а не заказ еды. То есть сайт умеет собирать контакты, просто не делает этого
на главном для себя сценарии.

## 1.9. Reservation

Работает корректно и является **самой проработанной частью сайта**:

- 7 полей: имя, телефон, дата, время, гости, повод, пожелания;
- маска телефона `+998 XX XXX XX XX` (строки 4442–4520);
- `guestDate.min` = сегодня — прошедшую дату выбрать нельзя;
- полный payload уходит в Telegram;
- экран успеха с автоскроллом.

**Парадокс сайта:** бронь стола (второстепенный сценарий) реализована полностью,
а заказ еды (основной сценарий) — нет.

Замечание к UI формы: `.form-field label` реализованы как плавающие подписи,
но валидация полностью отдана браузеру (`required`) — своих сообщений об ошибке нет.

## 1.10. Delivery information

**Раздела о доставке на сайте нет.** Ни блока, ни строки в футере, ни FAQ.

Пользователь не может узнать:
- доставляют ли вообще,
- в какие районы,
- сколько стоит доставка,
- есть ли бесплатная доставка от суммы,
- есть ли минимальная сумма заказа,
- сколько ждать,
- как оплатить (наличные, карта, онлайн),
- режим работы.

Для сервиса доставки еды это один из двух-трёх главных барьеров к заказу.

## 1.11. Mobile UX

Один-единственный брейкпоинт на весь сайт:

```css
@media(max-width:700px){ ... }     /* строка 1744 — и это всё */
```

Нет отдельной адаптации под планшет (768–1024) и под крупные телефоны.
Диапазон 700–1000px получает десктопную сетку на узком экране.

Размеры шрифтов внутри мобильного брейкпоинта:

```css
.add-product{ font-size:5.5px; }        /* главная кнопка конверсии */
.product-description{ font-size:8px; }
.product-name{ font-size:10px; }
.menu-tab{ font-size:7px; }
.footer-bottom{ font-size:7px; }
.cart-total-label{ font-size:8px; }
.checkout-button{ font-size:8px; }
```

**5.5px** — это реальное значение в продакшн-коде для кнопки «ДОБАВИТЬ В ЗАКАЗ».
Физически это примерно 0.7 мм высоты буквы на экране телефона. Минимально
читаемым размером считается 12px, комфортным для интерфейса — 14–16px.

Размеры целей нажатия:

| Элемент | Размер | Норма |
|---|---|---|
| `.qty-button` | 25×25 | 44×44 |
| `.cart-close` | 35×35 | 44×44 |
| `.add-product` | высота ~28px | 44 |
| `.menu-tab` | высота ~20px | 44 |

Прочее:
- сетка товаров на мобильном `1fr 1fr` при ширине карточки ~150px — на 360px экране
  фото становится ~150×190, а подпись 8px;
- `env(safe-area-inset-bottom)` не учитывается — на iPhone с индикатором жеста
  нижние элементы попадают под системную полосу;
- кастомный курсор корректно отключён на тач-устройствах — это сделано правильно;
- `hero` высотой 600vh на мобильном = очень долгий скролл до контента.

# ЧАСТЬ 2 — UI AUDIT

## 2.1. Typography

Шрифт — **Manrope** (300/400/500/600). Выбор хороший, современный, нейтральный.

Проблема — **отсутствие шкалы.** В файле встречается около 20 различных
значений `font-size`, назначенных вручную:

```
5.5px · 7px · 8px · 8.5px · 9px · 10px · 11px · 13px · 15px · 16px ·
18px · 19px · 20px · 24px · clamp(45px,6vw,90px) · clamp(95px,17vw,280px) · 17vw · 18vw · 19vw
```

Между 11px и 24px — почти пустота, при этом весь основной текст сайта
живёт в диапазоне **7–11px**. Это не «минимализм», это нечитаемость:
основной текстовый размер на сайте примерно вдвое меньше нормы.

Заголовки, наоборот, экстремально крупные (`17vw`–`19vw`). Итог — контраст
не «иерархия», а «либо гигантское, либо микроскопическое», без середины.

Плюсы: аккуратный `letter-spacing` в заголовках (`-.06em … -.085em`),
хороший `line-height` в текстовых блоках (1.8–1.9).

## 2.2. Spacing

Отступы задаются в основном в `vh`/`vw` (`padding:10vh 5vw`, `gap:5vw`).
Единой шкалы нет. Значения: `7px, 9px, 10px, 12px, 13px, 14px, 15px, 17px,
20px, 22px, 24px, 25px, 30px, 35px, 45px, 50px, 60px` — произвольные.

Следствие: вертикальный ритм не читается, блоки не выглядят частями одной системы.

## 2.3. Grid

```css
.products{ grid-template-columns: ... }
.footer-main{ grid-template-columns:2fr 1fr 1fr; }
.precision-main / .omakase-content / .reservation-content — свои сетки
```

Единой сетки/контейнера нет. Каждая секция определяет свою колоночную схему,
`max-width` контейнера не задан вообще — на мониторе 2560px контент растягивается
по всей ширине, строки текста становятся чрезмерно длинными.

## 2.4. Colors

```css
--bg:#050505;  --bg2:#080808;  --card:#0c0c0c;
--white:#f2efe8;  --muted:rgba(242,239,232,.42);
--line:rgba(242,239,232,.12);  --red:#d94a43;
```

Палитра **хорошая** — это одна из сильных сторон сайта. Тёплый белый `#f2efe8`
вместо чистого белого даёт дорогое ощущение, графитовый фон работает.

Проблемы:
- переменная `--red` объявлена, но акцент **почти не используется** —
  красный не работает ни на CTA, ни на активном табе, ни на цене;
- вторичный текст задаётся десятками разных прозрачностей вручную
  (`.22 .25 .35 .4 .42 .5`) вместо 2–3 системных токенов;
- контраст: `rgba(242,239,232,.22)` на `#020202` даёт примерно **2.3:1** —
  это ниже минимума WCAG AA (4.5:1) и на светлом экране телефона на улице
  просто не читается.

## 2.5. Hierarchy

Внутри имиджевых секций иерархия построена уверенно: eyebrow → крупный
заголовок → текст. Это выглядит профессионально.

Но **сквозной иерархии страницы нет**: все 5 секций оформлены одинаково
(номер, название, «KYOTO · JAPAN», гигантский заголовок). Меню — то есть
единственный коммерческий блок — визуально равнозначно блоку «Не просто ужин.
Состояние.». Пользователь не считывает, что здесь главное.

## 2.6. Buttons

Три разных вида кнопок, ни одна не выглядит как основное действие:

```css
.add-product{ border:1px solid rgba(...,.2); background:none; }  /* контурная */
.checkout-button{ background:var(--white); color:#050505; }      /* белая */
.omakase-button{ background:none; }                              /* текстовая */
```

- Главная кнопка конверсии `.add-product` — **контурная, прозрачная, 5.5px на мобильном.**
  Слабейший визуальный вес на странице отдан самому важному действию.
- Нет системы состояний: `:focus-visible` не определён ни для одной кнопки,
  `:disabled` не оформлен, `:active` отсутствует.
- Нет иерархии primary / secondary / tertiary.

## 2.7. Cards

```css
.products.has-hover .product-card:not(.is-hovered){ opacity:.35; }
```

При наведении на одну карточку **все остальные затемняются до 35%**.
Эффект выглядит эффектно в портфолио и вредит в магазине: пользователь
сканирует меню взглядом, а сетка постоянно «мигает» под курсором.

Ещё:
- карточка полностью плоская — нет поверхности, нет границы, товар «висит» на фоне;
- порядок элементов: фото → название+цена → описание → кнопка.
  Описание разрывает связку «цена → действие»;
- `.product-label` («KYOTO / SALMON») дублирует название товара — визуальный шум;
- параллакс-сдвиг фото за курсором на 10px — приятно на десктопе, но требует
  `mousemove`-обработчик на каждой карточке.

## 2.8. Imagery

Фотографии — **сильная сторона сайта**. Качественные, тёплые, с правильным
светом (Unsplash, единый визуальный ряд).

Технические проблемы:
- один размер для всех устройств: `w=1000` грузится и на 4K-монитор, и на телефон 360px;
- нет `srcset` / `sizes`;
- нет `width`/`height` → **layout shift** при загрузке;
- `alt="SALMON"` дублирует видимый заголовок — для скринридера это повтор,
  а не описание;
- **в hero фотографий еды нет вообще** — самый важный экран сайта не показывает продукт.

## 2.9. Header

Разобран в 1.2. Кратко по UI: 90px высоты, три элемента, шрифт 8px,
корзина без фона и без границы — выглядит как подпись, а не как кнопка.
Признака «здесь можно нажать» у корзины практически нет.

## 2.10. Footer

```html
KYOTO | NAVIGATION | CONTACT
+998 00 000 00 00      ← заглушка
hello@kyoto.uz
TASKENT · UZBEKISTAN
```

- **Телефон — незаполненная заглушка `+998 00 000 00 00`.**
  На сайте доставки еды это прямая потеря заказов от тех, кто хочет позвонить.
- Нет режима работы, нет адреса, нет соцсетей, нет карты, нет юридической информации.
- Размер текста 7–9px, контраст ниже AA.

## 2.11. Responsive behaviour

Уже разобрано в 1.11. Дополнительно по UI:
- `.footer-main{grid-template-columns:1fr 1fr}` на мобильном при трёх колонках
  контента — третья колонка переносится и ломает ритм;
- `.products{gap:45px 12px}` — вертикальный зазор в 4 раза больше горизонтального,
  сетка выглядит рассыпанной;
- горизонтальный скролл табов сделан правильно (`overflow-x:auto` + скрытый скроллбар) —

## 2.13. Безопасность — требует отдельного решения

```js
const TG_CONFIG = {
    token: "8658645102:AAHz...",   // строка 2944
    chatId: "689217749"
};
```

Токен Telegram-бота и `chat_id` лежат в клиентском JavaScript — то есть
**видны любому посетителю сайта** через «Просмотр кода страницы».

Практический риск: посторонний может от имени вашего бота отправлять сообщения
в ваш чат (например, засыпать его ложными заказами), а также прочитать
историю обновлений бота.

Это не следствие редизайна — так на сайте сейчас. Но об этом нужно знать
и принять решение. Варианты разберём в стратегии.

# ЧАСТЬ 6 — СТРАТЕГИЯ KYOTO 2.0

## 6.1. Формулировка

Текущий сайт отвечает на вопрос **«кто мы»**.
KYOTO 2.0 должен отвечать на **«кто мы» за 3 секунды**, а всё остальное время —
на вопрос **«что заказать и как это получить»**.

Стратегия не в том, чтобы сделать сайт красивее. Он уже красивый.
Стратегия — **достроить до него работающий продукт, не потеряв характер.**

## 6.2. Три опоры

**Опора 1. Заказ должен доходить.**
Без этого остальное не имеет значения. Checkout собирает имя, телефон, способ
получения, адрес и комментарий, и отправляет их через **существующий транспорт** —
тот же Telegram-бот, тот же `chat_id`, та же функция `sendTelegramMessage()`.
Новый API не изобретается, бэкенд не появляется, бизнес-логика не меняется —
расширяется только полезная нагрузка сообщения.

**Опора 2. Путь до заказа — не длиннее 4 действий.**

```
Вход → [Смотреть меню] → [+ Добавить] → [Перейти к заказу] → [Оформить]
```

Корзина видна всегда. Количество меняется на карточке. Оформление — в той же
панели, вторым шагом, без перезагрузки и регистрации.

**Опора 3. Премиальность через контроль, а не через количество.**
Бренд усиливается тем, что убирается лишнее: 4 имиджевые секции → 1 сильная,
20 размеров шрифта → 7, декоративная 3D-геометрия → воздух и фотография.
Красный акцент начинает работать точечно: активный таб, бейдж «ХИТ», цена акции.

## 6.3. Новая структура главной


## 6.4. Принцип честности данных

Требование «не выдумывай цифры» будет выполнено буквально, через конфиг:

```js
const SITE = {
  phoneDisplay:"",                                       // ← нужен от вас
  stats:{ rating:"", orders:"", clients:"", positions:"" },
  promo:{ active:false, text:"−30 000 сум на первый заказ" },
  delivery:{ fee:null, freeFrom:null, minOrder:null, timeText:"", zones:"" },
  hours:""
};
```

**Пустое значение → блок не рендерится.** Ни один придуманный рейтинг,
ни одно выдуманное количество заказов на сайт не попадёт.
Акция «−30 000 сум» будет выключена (`active:false`) — по коду подтвердить
её активность невозможно; включается одним значением, когда вы подтвердите.

Вместо выдуманных цифр в hero — утверждения, истинные по устройству самого
сервиса: «Заказ без регистрации», «Доставка по Ташкенту», «Оформление за минуту».

# ЧАСТЬ 7 — ЧТО НУЖНО ОТ ВАС

Три вопроса, ответы на которые нельзя получить из кода. Работу они не блокируют —

заполните конфиг. Но без ответов сайт выйдет с дырами в местах, где нужны факты.

- Реальный телефон (сейчас `+998 00 000 00 00`).

- Адрес ресторана.
- Ссылки на Instagram / Telegram.

**2. Условия доставки**
- Стоимость доставки, бесплатная доставка от суммы, минимальный заказ.
- Среднее время доставки.
- Зоны / районы Ташкента.
- Способы оплаты (наличные, карта курьеру, Payme / Click).

**3. Акция и ассортимент**
- Акция «−30 000 сум на первый заказ» действительно активна? Условия?
- Есть ли реальные категории «Горячее» и «Супы» с блюдами? Система будет готова
  их принять — категория без товаров просто не отображается, поэтому добавить их

- Какие 4–6 позиций из 12 действительно самые продаваемые — чтобы блок «Хиты»
  был честным, а не назначенным мной.

**Отдельно — решение по безопасности.**

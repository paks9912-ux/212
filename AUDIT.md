# KYOTO 2.0 — Premium Conversion
## UX / UI / CRO аудит и план реализации

> **Источник аудита.** Домен `kyoto.uz` заблокирован сетевой политикой этого окружения,
> поэтому аудит проведён по исходному коду репозитория (`index.html`, 4586 строк,
> один файл: разметка + CSS + JS). Это и есть код сайта — то есть источник правды
> для всего, что реально можно изменить.

# 1. UX AUDIT

## 1.1. Что сейчас представляет собой сайт

Сайт технически — **не сайт доставки, а сайт-визитка ресторана** с прикрученным
каталогом. Единственный способ «оформить заказ» — это кнопка, которая отправляет
в Telegram список позиций **без имени, телефона и адреса гостя**.

Структура текущей главной:

| # | Блок | Высота | Продаёт еду? |
|---|------|--------|--------------|
| — | HERO — анимация текста `TASTE → SILENCE → KYOTO` | **600vh** (6 экранов) | нет |
| 01 | THE RITUAL — «ТОЧНОСТЬ в каждом движении» | ~1 экран | нет |
| 02 | MENU — 4 таба, 12 товаров | ~2 экрана | **да** |
| 03 | OMAKASE — «Вам не нужно выбирать» | ~1 экран | нет |
| 04 | EXPERIENCE — «Не просто ужин. Состояние.» | ~1 экран | нет |
| 05 | RESERVATION — форма брони стола (7 полей) | ~1.5 экрана | нет |
| — | FOOTER | ~0.5 экрана | нет |

**Меню начинается примерно на 8-м экране прокрутки.** До первой фотографии еды
пользователь должен сделать ~6 свайпов по анимированной типографике.

## 1.2. Путь пользователя: Главная → меню → блюдо → добавить → корзина → заказ

Прошёл путь по коду. Проблемы по шагам:

**Шаг 1 — Главная.**
`.hero{height:600vh}` — скролл-джекинг на 6 экранов. Ни одной фотографии еды.
Ни слова о доставке. Ни цены. Единственный CTA — `Discover the ritual ↓` —
ведёт не в меню, а в ещё один имиджевый блок (`#ritual`).
Заголовка `<h1>` на странице нет вообще — «KYOTO» собран из `<span>` внутри `<div>`.

**Шаг 2 — Меню.**
Табы `SUSHI / ROLLS / SETS / SAKE` — латиницей, при том что весь остальной
контент на русском. Нет категорий «Хиты», «Горячее», «Супы». Нет поиска,
нет сортировки, нет признака популярности. 12 позиций — при этом бренд
позиционируется как ресторан с большим ассортиментом.

**Шаг 3 — Карточка блюда.**
Отдельной страницы/модалки блюда нет — только карточка в сетке. Само по себе
это нормально для скорости, но карточка на мобильном нечитаема:

```css
.add-product{ font-size:5.5px; }   /* кнопка «ДОБАВИТЬ В ЗАКАЗ» */
.product-description{ font-size:8px; }
.product-name{ font-size:10px; }
```

**5.5px** — это не опечатка в аудите, это реальный размер шрифта главной
кнопки конверсии на мобильном.

**Шаг 4 — Добавление.**
Первый клик — товар добавлен. **Второй клик по той же кнопке не увеличивает
количество, а открывает корзину** (`if(cart[productId]){ openCart(); return; }`).
Чтобы заказать 2 ролла, нужно: добавить → открыть корзину → нажать `+` →
закрыть корзину → вернуться к меню. Это 5 действий вместо одного.

**Шаг 5 — Корзина.**
Корзина видна **только внутри hero-секции** — `.nav{position:absolute}` внутри
`.hero`. После прокрутки до меню кнопка корзины физически уходит за экран.
На мобильном корзины нет вообще ни в каком виде на 90% высоты страницы.
Счётчик товаров есть, суммы нет.

**Шаг 6 — Оформление заказа. Главный дефект сайта.**

```js
// Всё, что уходит в Telegram при нажатии «ОФОРМИТЬ ЗАКАЗ»:
message = "🍱 НОВЫЙ ЗАКАЗ — KYOTO\n\n1. PHILADELPHIA x 2 = 178 000 сум\nИТОГО: ..."
```

Ни имени. Ни телефона. Ни адреса. Ни способа получения. Ни комментария.
**Заказ, который физически невозможно выполнить.** Ресторан получает в
Telegram список блюд от анонима. Форма контактов существует только у
бронирования стола — не у заказа.

## 1.3. Где пользователь запутается / уйдёт

- **Уйдёт** на 600vh hero, не поняв, что здесь можно заказать еду.
- **Потеряет корзину** — она уезжает вместе с hero.
- **Не поймёт, что делать дальше** — после добавления товара нет ни одного
  указателя на следующий шаг.
- **Сделает лишний клик** — второй клик по «Добавить» открывает корзину.
- **Не сможет нажать** — цели меньше 44px: `.qty-button` 25×25, `.cart-close` 35×35.
- **Не найдёт условия доставки** — блока о доставке на сайте нет вообще.
- **Не найдёт телефон** — в футере стоит заглушка `+998 00 000 00 00`.

## 1.4. Технический аудит

| Область | Состояние |
|---|---|
| `<h1>` | **отсутствует** |
| `meta description` | **отсутствует** |
| Open Graph / Twitter | **отсутствуют** |
| `canonical` | **отсутствует** |
| favicon | **отсутствует** |
| structured data | **отсутствует** |
| `@media` запросов | **один** (`max-width:700px`) — планшетов и крупных телефонов нет |
| `alt` у фото | есть, но дублирует название (`alt="SALMON"`) |
| focus states | **отсутствуют** — навигация с клавиатуры невозможна визуально |
| `prefers-reduced-motion` | не учитывается |
| размеры изображений | не заданы → layout shift |
| `srcset` | нет — на телефон грузится картинка шириной 1000px |
| rAF-циклы | 2 бесконечных (курсор + hero), работают всегда |

## 1.5. CRO: что мешает заказать

1. **Заказ невозможно выполнить** — нет контактов клиента.
2. **До меню 8 экранов.**
3. **Корзина исчезает.**
4. **Нет ответа на вопрос «сколько стоит доставка и когда привезут».**
5. **Нет причины заказать именно сейчас** — ни акции, ни хитов, ни срочности.
6. **Нет социального доказательства.**
7. **Кнопка конверсии 5.5px.**
8. **Форма брони стола (7 полей) сильнее выражена, чем заказ еды** — сайт
   оптимизирован под бронь, а не под доставку.

## 1.6. Что заставляет заказать (что уже работает — сохранить)

- Сильный, узнаваемый визуальный характер: графит, воздух, сдержанный красный.
- Хорошая food-фотография в карточках.
- Аккуратная типографика с большими заголовками.
- Корзина переживает перезагрузку (`localStorage: kyoto-cart`).
- Telegram-интеграция — мгновенное уведомление ресторана, без бэкенда.
- Работающая форма брони с маской телефона `+998 XX XXX XX XX`.

# 5. НОВАЯ СТРУКТУРА МЕНЮ

Категории описаны данными, а не разметкой:

```js
const CATEGORIES = [
  { key:"hits",   label:"Хиты"     },  // виртуальная: product.hit === true
  { key:"rolls",  label:"Роллы"    },
  { key:"sets",   label:"Сеты"     },
  { key:"sushi",  label:"Суши"     },
  { key:"hot",    label:"Горячее"  },
  { key:"soups",  label:"Супы"     },
  { key:"drinks", label:"Напитки"  }
];
```

**Категория без товаров не отображается.** «Горячее» и «Супы» уже описаны в
системе — чтобы они появились на сайте, достаточно добавить объекты в массив
`products`, менять разметку не нужно. Категории `sake` переименованы в `drinks`
(**id товаров не тронуты**, поэтому корзины пользователей не ломаются).

Поведение табов: sticky под шапкой, горизонтальный скролл на мобильном,
активный таб автоматически подскроллен в зону видимости, состояние
не сбрасывает позицию страницы.

# 6. НОВЫЙ UX КОРЗИНЫ

**Постоянная видимость**

- Desktop: кнопка корзины в sticky-шапке, с количеством и суммой.
- Mobile: sticky bottom bar, появляется после первого товара и не исчезает:
  `🛒 4 товара · 287 000 сум → Перейти к заказу`
  Учтён `env(safe-area-inset-bottom)` для iPhone.

**Добавление**

Карточка в состоянии «пусто» → кнопка `ДОБАВИТЬ`.
После нажатия кнопка **на месте** превращается в степпер `− 1 +`.
Никаких модалок, никаких переходов. Тост `✓ Добавлено` + пульс счётчика.

**Внутри корзины**

Фото · Название · Цена за штуку · Степпер `− N +` · Сумма позиции · Удалить
Итого · Стоимость доставки (если задана в конфиге) · **[ Оформить заказ ]**

# 8. DESIGN DIRECTION

## Цвет

```css
--bg:        #0A0A0A   /* фон */
--surface:   #141414   /* карточки, панели */
--graphite:  #1C1C1C   /* границы блоков, поля ввода */
--text:      #FFFFFF
--muted:     #A1A1A1   /* вторичный текст */
--accent:    #D94A43   /* сдержанный красный — только акценты и цены-акции */
```

Красный не используется как фон больших плоскостей. Только: активный таб,
бейдж «ХИТ», плашка акции, hover основной кнопки.

## Типографика

Одна шкала, 7 ступеней. Никаких произвольных `5.5px` / `7px` / `8px` / `9px`.

```
display  clamp(48px, 9vw, 128px)   H1, вывеска KYOTO
h2       clamp(32px, 5vw, 64px)
h3       clamp(20px, 2.4vw, 28px)
lead     17px / 1.6
body     15px / 1.65
small    13px / 1.5
caption  12px, letter-spacing .18em, uppercase
```

## Пространство

Шкала 4px: `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128`.

## Радиусы и тени

```
--r-sm: 6px    --r-md: 10px    --r-lg: 14px    --r-pill: 999px
--shadow: 0 8px 32px rgba(0,0,0,.4)   /* очень мягкая, только для sticky-элементов */
```

Не «огромные rounded cards» — радиус максимум 14px.

## Анимация

Только: `fade`, `reveal on scroll` (IntersectionObserver, один раз),
`scale(1.03)` на hover фото, плавный счётчик корзины.
Длительности 180–420ms, кривая `cubic-bezier(.16,1,.3,1)`.
Всё выключается при `prefers-reduced-motion: reduce`.

# 9. ЧЕСТНОСТЬ ДАННЫХ

Требование «НЕ ВЫДУМЫВАЙ ЦИФРЫ» выполнено буквально.

В коде появился конфиг `SITE` — единственное место, где живут реальные данные:

```js
const SITE = {
  phoneDisplay: "+998 00 000 00 00",   // ← ЗАГЛУШКА из текущего сайта
  stats:   { rating:"", orders:"", clients:"", positions:"" },  // пусто = блок не рендерится
  promo:   { active:false, text:"−30 000 сум на первый заказ" },
  delivery:{ fee:null, freeFrom:null, minOrder:null, timeText:"" }
};
```

**Ни один блок с цифрами не показывается, пока значение пустое.**

- Рейтинг, количество заказов, количество клиентов — **не придуманы, поля пустые.**
- Акция «−30 000 сум на первый заказ» — **выключена** (`active:false`), потому что
  подтвердить её активность по коду невозможно. Включается одним значением.

токен Telegram-бота и `chat_id` находятся в клиентском JS — то есть публично доступны

отправки на минимальный прокси (Cloudflare Worker / Vercel Function), это ~20 строк
кода и не затрагивает фронтенд. В рамках этого редизайна оставлено как есть.

# Конвейер фриланс-заказов

Находит заказы в легальных источниках каждые пять минут, отсеивает мусор правилами
без единого запроса к модели, оценивает остаток через Claude и присылает в Telegram
только то, где **ожидаемая прибыль за час** выше вашей цели. Готовит три варианта
отклика — отправляете вы. Ведёт журнал откликов, проектов, времени и денег и
считает реальный доход за час по каждой услуге.

Архитектура и обоснование решений — в документе [«Конвейер фриланс-заказов»](https://claude.ai/code/artifact/1f20c07b-e961-4572-87ff-57672c3b5917).

## Что нужно

- Node.js 22.12 или новее (используется встроенный SQLite)
- Ключ Claude API
- Telegram-бот от @BotFather и ваш chat id (узнать у @userinfobot)

## Запуск за десять минут

```bash
cd freelance-pipeline
npm install
cp .env.example .env          # впишите ANTHROPIC_API_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_ADMIN_CHAT_ID
```

Откройте `config/profile.yml` и замените предположения своими цифрами: целевой
доход за час, минимальный бюджет, имя. Список услуг уже заполнен по вашему ТЗ —
поправьте ключевые слова, если что-то ищете иначе.

```bash
npm run doctor                # проверит ключи, конфиг и сеть до каждого источника
npm test                      # 34 проверки: фильтр, ранжирование, источники, деньги, калибровка
npm run run                   # один проход: собрать → оценить → отчёт в консоль
npm run add -- "https://www.upwork.com/jobs/~01…"   # оценить заказ по ссылке
npm run add -- "Нужен лендинг для кофейни, бюджет 25 000 руб"   # или по тексту
npm run daemon                # бот + панель http://127.0.0.1:8787 + опрос по расписанию
```

Первым делом напишите боту `/help`.

Upwork, Kwork, FL.ru и любые площадки без API работают через ручную вставку:
скиньте боту ссылку или текст — получите оценку и черновики за минуту.
Парсинг и автоотклики там запрещены правилами, и система этого не делает.

## Как считается очередь

**Этаж 1 — правила, без модели** (`config/filters.yml`): язык, возраст заказа,
бюджет ниже минимума, стоп-фразы, число откликов, хотя бы одно ключевое слово
из ваших услуг. Отсеянное хранится с причиной — пригодится для калибровки.

**Этаж 2 — модель** возвращает восемь факторов от 0 до 1, оценку часов и
обоснование. Веса факторов — в `config/weights.yml`, их можно править руками.

**Что строит очередь** — не балл, а ожидаемые деньги за час:

```
ожидаемые $/час = бюджет × p(победы) × (1 − комиссия) / (часы + накладные на отклик)
```

Вероятность победы — априорная по источнику, умноженная на конкуренцию,
попадание в тему и свежесть. Первые 50 откликов это оценка «на глаз»; после —
её заменяет статистика ваших исходов (`/calib` в боте).

Категории: 🔥 HOT — если выиграть, $/час вдвое выше цели, шанс реальный и
заказу меньше 30 минут; 💰 HIGH PROFIT — бюджет от $500; ⚡ QUICK WIN — до
3 часов; 🤖 HIGH AI — от 80% работы на AI; ⭐ GOOD CLIENT — история и
подтверждённая оплата; 🟡 MAYBE — в очередь без алерта; 🔴 REJECT — в базу.

Режим `mode: reviews` в профиле — для первого месяца: конкуренция и деньги
весят меньше, показываются и средние заказы, если они быстрые и без риска.

## Бот

| Команда | Что делает |
|---|---|
| `/add <ссылка или текст>` | оценить заказ вручную |
| `/top` | лучшие заказы очереди |
| `/today` | цифры дня и месяца |
| `/pause` · `/resume` | остановить или включить алерты |
| `/won <id>` · `/lost <id>` | исход отклика; `/won` создаёт проект |
| `/projects` | активные проекты |
| `/time <проект> <минуты>` | учесть время |
| `/paid <проект> <сумма> [валюта] [комиссия]` | оплата; считает $/час по проекту |
| `/status <проект> IN_PROGRESS` | сменить статус |
| `/reply <проект> <текст клиента>` | разобрать сообщение и предложить ответ |
| `/plan <проект>` | разобрать ТЗ: чего не хватает, вопросы клиенту, шаги с часами |
| `/tasks <проект>` · `/done <задача>` | список задач из плана и отметка |
| `/deliver <проект>` | сообщение о сдаче, чек-лист перед отправкой, идея следующей работы |
| `/calib` | что говорят исходы |

Под каждым алертом три кнопки: «Отклик» пишет три варианта, «Позже» отложит,
«Не моё» спросит причину — причины идут в калибровку.

## После победы

Заказ выигран, `/won <id>` создал проект. Дальше четыре шага, все через бота
или консоль:

1. **`/plan`** — Claude разбирает ТЗ: что нужно, чего не хватает, готовые
   вопросы клиенту, шаги с честной оценкой часов и долей AI, риски, критерии
   приёмки. Шаги становятся задачами проекта, оценка часов и доля AI
   записываются в проект и потом попадают в статистику.
2. **Работа.** Для лендингов есть `templates/landing/`: три файла без
   фреймворков, проходят QA без замечаний, под клиента меняются тексты, цвета
   в `:root` и адрес формы. Отмечайте задачи через `/done`, время через `/time`.
3. **`npm run qa -- <папка или url>`** — Playwright прогоняет сайт на телефоне,
   планшете и десктопе: ошибки скриптов, битые ссылки и якоря, картинки без
   alt, форма без обработчика, горизонтальный скролл, мелкие кнопки, мелкий
   текст, вес и скорость, мета-теги. Отчёт в `qa-reports/`, критичные
   проблемы дают ненулевой код выхода. Цикл «нашёл → починил → прогнал снова»
   до чистого отчёта. Первый запуск скачает браузер: `npx playwright install chromium`.
4. **`/deliver`** — сообщение клиенту о сдаче на его языке, чек-лист, что
   проверить перед отправкой, и одна честная идея следующей работы.
   Отправляете вы.

## Калибровка

Каждый отказ с причиной и каждый исход `/won` или `/lost` копятся в базе.
После 50 откликов и 5 побед `npm run calibrate` делает две вещи: заменяет
априорные вероятности победы по источникам вашей статистикой, сглаженной к
исходной, и подкручивает веса факторов в пределах ±40%: фактор, который у
выигранных откликов стабильно выше, чем у проигранных, начинает весить
больше. Результат хранится в базе и подхватывается при следующей оценке;
`config/weights.yml` остаётся вашей ручной настройкой поверх. `/calib`
показывает, что уже видно по данным.

## Модели и стоимость

Скоринг потока — `claude-haiku-4-5`, отклики и разбор переписки —
`claude-opus-5`. Меняются через `MODEL_SCORE`, `MODEL_PROPOSAL`, `MODEL_REPLY`
в `.env`. Стабильный префикс (рубрика + профиль + кейсы) кэшируется, поэтому
при опросе каждые 5 минут почти каждый запрос попадает в кэш. Стоимость каждого
запроса пишется в базу и видна в `/today`.

## Безопасность

Ключи только в `.env` и переменных окружения; в репозиторий уходит
`.env.example`. Бот отвечает только вашему chat id. Панель слушает
`127.0.0.1` — наружу не торчит; для доступа с телефона поставьте перед ней
любой reverse proxy с паролем. Логи маскируют всё, что похоже на ключ.
Система не отправляет отклики и сообщения сама, не трогает деньги и не
обходит правила площадок.

# Аналитика посещений и админка

Отвечает на два вопроса: **сколько человек сегодня заходило на сайт** и **на каком шаге
каждый из них ушёл, не купив**.

## Запуск

```bash
ADMIN_TOKEN=длинный-случайный-пароль node server.js
```

| Адрес | Что это |
|---|---|
| `http://адрес:8080/` | сайт |
| `http://адрес:8080/admin?key=ВАШ_ПАРОЛЬ` | админка |

Зависимостей нет — только встроенные модули Node. Переменные окружения: `SITE_PORT`
(по умолчанию 8080), `ADMIN_TOKEN` (обязателен — без него админка и статистика отключены),
`TRUST_PROXY=1` если стоит за nginx.

Данные — в `data/analytics/ГГГГ-ММ-ДД.jsonl`, по строке на событие. В git не попадают.
Сутки считаются по ташкентскому времени, а не по UTC.

## Что видно в админке

**Итог дня** — сколько зашло, сколько купило, конверсия, сколько денег осталось в брошенных
корзинах, сколько было сбоев отправки заказа.

**Путь до заказа** — шесть шагов с числом дошедших и подсветкой шага, где теряется больше всего:

```
Зашёл на сайт → Дошёл до меню → Положил в корзину → Открыл корзину → Нажал «оформить» → Оформил
```

**Почему ушли не купив.** Это не догадка о мыслях гостя, а факт: где именно оборвался путь.

| Причина | Что это значит |
|---|---|
| Нажал «оформить» — заказ не ушёл | Техническая поломка. Готовое решение купить, потерянные деньги |
| Открыл корзину и передумал | Увидел итоговую сумму или не нашёл условий доставки |
| Положил в корзину и отвлёкся | Решение почти принято — таких догоняет ретаргет |
| Посмотрел меню, ничего не выбрал | Не нашёл нужного блюда или не устроила цена |
| Не долистал до меню | Заставка перед меню длиной в шесть экранов |
| Закрыл сразу (до 5 секунд) | Не то, чего ждал по рекламе, либо сайт долго грузился |

**Брошенные корзины** — сумма, состав, до какого шага дошёл, сколько минут провёл.

**Откуда пришли** — по UTM-меткам: конверсия считается отдельно по каждой рекламной кампании,
так что видно, какое объявление приводит покупателей, а какое просто трафик.

**По часам** — сверять с пиками из Poster: обед 12–13, вечер 19–20.

## Приватность

IP-адреса не сохраняются: нужны только для ограничения частоты запросов и живут в памяти.
Идентификатор сессии случайный и живёт до закрытия вкладки. Персональных данных нет.

Страница `admin.html` сама по себе данных не содержит — она запрашивает их у `/api/stats`,
а тот проверяет ключ. Но отдавать её статикой в обход `server.js` всё равно не стоит.

## Если админка живёт в проекте с ботами

Сбор уже встроен в `index.html` и шлёт события на `ANALYTICS_ENDPOINT` (`/api/track`).
Чтобы принимать их в другом проекте, перенесите из `server.js` три части: `handleTrack` (приём),
`loadSessions` + `buildStats` (разбор дня в сессии и агрегация) и роут `/api/stats`.
Событие — плоский JSON с полями `sid` и `type`, дальше по типу. `admin.html` работает с любым
сервером, который отдаёт `/api/stats` в том же виде.

Выключить сбор полностью — очистить `ANALYTICS_ENDPOINT` в `index.html`.
